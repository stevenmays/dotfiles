Build a Large Language Model · Ch. 2, §2.6–2.8

A tensor is a grid of numbers with a shape

Forget the physics definition. In PyTorch a tensor is an n‑dimensional array plus three facts: its shape, its dtype, and its device. The shape is the part that matters for Chapter 2. Every step in the second half of the chapter takes a tensor of one shape and returns a tensor of another shape. If you can track the shape, you understand the code.

The idea

Rank = how many indices name one number

A scalar needs 0 indices. A vector needs 1 (v[2]). A matrix needs 2 (m[row, col]). A 3D tensor needs 3 (x[batch, position, feature]). That's all "dimension" means here: one more axis to index along.

Each axis gets a job. In Chapter 2 the jobs are always the same three: which sequence in the batch, which position in the sequence, and which feature of the vector.

§2.6 · Data sampling

The sliding window makes a 2D tensor of token IDs

The tokenizer turns text into one long list of integers. GPTDatasetV1 cuts that list into chunks of max_length tokens. The target for each chunk is the same chunk shifted right by 1 token, because the model's job is to predict the next token. stride sets how far the window moves between chunks.

§2.7 · Token embeddings

        
An embedding layer is a lookup table

        

          Think of a spreadsheet. Each row is one word in the vocabulary, and
          the row number is the token ID. Each row holds a short list of numbers
          for that word. To embed a token, you go to its row and copy it out.
          That's the whole operation.
        

        

          The book's toy table has 6 words with 3 numbers each, so it's 6 rows ×
          3 columns. The numbers start random, and training adjusts them. Click
          an ID below to change it and see which row gets copied.
        

        

          

            

              input_ids
              

            

            

            

          

          

            Values are random stand-ins; the book's printout uses
            torch.manual_seed(123). The weights start random and
            training adjusts them. The output shape is the input shape with one
            new axis on the end: [4] →
            [4, 3].
          

        

        

          Why not a one-hot vector times a matrix? That gives the same result. A
          one-hot row times W selects one row of W.
          The embedding layer skips the multiplication and indexes directly, so
          it's much faster. Both are differentiable, so backprop updates exactly
          the rows that were used.
        

      


      

        
§2.8 · Positional embeddings

        
Broadcasting adds one position table to every row in the batch

        

          Token embeddings don't know where a token sits. Token 40 gets the same
          vector at position 0 and at position 3. GPT fixes this with a second
          embedding layer, indexed by
          torch.arange(context_length) instead of token IDs. Its
          output has shape
          [4, 256]: one vector per position, no batch axis.
        

        

          The book then adds [8, 4, 256] +
          [4, 256]. Those shapes differ, so PyTorch
          broadcasts: it lines the shapes up from the right, sees the
          smaller tensor is missing the leading batch axis, and reuses it for
          all 8 sequences. No copy is made in memory.

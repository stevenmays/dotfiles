# Frontend craft

Deliver an implemented design that has been inspected at desktop and mobile sizes. Preserve the user's product, framework, visual direction, and existing design system.

When the brief leaves visual choices open, choose a coherent direction with a clear typographic hierarchy, palette, layout, and one distinctive visual feature. Explore alternatives when the user requests options. A routine design decision does not require a new approval round.

Use relevant design capabilities available in the session. No particular external design skill is required. When another skill owns the build environment, follow its actual constraints without importing unrelated workflows.

Use photographs, illustrations, or generated media when they serve the content. Prefer the session's built-in image generation capability when available. Preserve an explicitly requested provider. Code-native diagrams, icons, and simple visual effects can stay in code. Missing optional media tooling does not block the rest of the interface. Do not create fake customer claims, metrics, testimonials, or logos.

Inspect the implemented interface in a browser at representative desktop and mobile widths. Check hierarchy, readability, overflow, keyboard operation, interaction states, and alignment with the brief. Capture screenshots when available. Report unavailable verification without inventing screenshots or scores.

For substantial design work, use an independent critic when authorized collaboration tools are available. Give the critic screenshots and the brief, not implementation rationale or past scores. Ask for concrete gaps in composition, typography, spacing, color, content, and interaction. The main agent can implement fixes; spawning a new implementer for each round is unnecessary.

Fix the largest observed gaps and recheck affected views. Stop when the brief and functional requirements are met and no material visual issue remains. If additional passes stop improving the result, describe the remaining limitation. Use comparisons to references when available; a numeric score is optional and is not proof of quality.

Make a subtraction pass: remove containers that group nothing, repeated labels, decorative effects without purpose, and copy that explains implementation details. Keep elements that support the aesthetic or usability, even if they also appear in common designs.

Complete the implementation, interactions, and relevant checks before handing back the result. Report the direction, assets used, verified views, and remaining gaps in a short handoff.
